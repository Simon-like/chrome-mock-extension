## 2. 优先级排序

### 🥇 P0 · 动态响应（F9 + F21）

**痛点**：现在只能返回固定 JSON。这意味着：

- 翻页时每一页返回一样的数据
- 按 id 查详情，返回的永远是同一条
- 搜索关键词不影响结果
- POST 提交后拿不到「回显提交内容」的响应

这是当前**最大的能力缺口** —— 一旦接口带参数，静态 Mock 立刻不够用。

**方案**：`bodyType: 'dynamic'` 时，`body` 存一段 JS 函数源码：

```js
(req) => ({
  list: Array.from({ length: req.query.size ?? 10 }, (_, i) => ({
    id: (req.query.page - 1) * 10 + i + 1,
    name: `商品 ${i + 1}`,
  })),
  total: 48,
  page: Number(req.query.page ?? 1),
})
```

`req` 需要提供：`url` `method` `query` `params`（路径参数）`body` `headers`。

**关键难点 —— 怎么执行这段代码**：

| 方案 | 问题 |
| --- | --- |
| `eval` / `new Function` | 扩展的 CSP 默认禁止；且注入层在页面上下文，会污染页面 |
| 在 Service Worker 里跑 | ❌ `xhr.send()` 是同步的，等不了跨进程返回（05 §1.2 已论证） |
| **在 MAIN world 用 `new Function`** | 可行 —— MAIN world 就是页面上下文，页面自己能执行 JS，我们也能。但要防止用户代码抛异常拖垮引擎 |

**倾向方案**：MAIN world 内 `new Function`，外面包 try/catch + 超时保护，
出错时回落到静态 body 并在请求面板标红。**引擎绝不能因为用户代码写错就崩掉。**

需要验证：`world: MAIN` 下 `new Function` 是否受页面 CSP 限制（有些站点设了
`script-src` 不含 `unsafe-eval`）。**这一步要先做个 Spike。**

**顺带解决 F21**：有了动态响应，「同一 URL 按参数返回不同数据」天然支持。

- 痛感 ★★★★★ · 成本 ★★★☆☆ · 学习价值 ★★★☆☆

### 🥈 P1 · 假数据生成（F10）

**痛点**：造 10 条商品数据要手写 10 个对象，改字段要改 10 遍。

**方案**：内置 Mock.js 语法，`bodyType: 'mockjs'`：

```json
{
  "list|10": [{ "id|+1": 1001, "name": "@ctitle(4,8)", "price|10-999.2": 1 }],
  "total": 48
}
```

Mock.js 体积约 60KB（gzip 后 ~20KB），全量打进注入脚本会让每个页面都多加载这些。
**倾向做法**：按需动态加载，或只实现常用占位符的轻量子集。

- 痛感 ★★★★☆ · 成本 ★★☆☆☆ · 学习价值 ★★☆☆☆

### 🥉 P2 · MCP Server（L2）

**这是这个项目最初的立项理由之一**，也是差异化最大的一块。架构预留（A1–A4）已经做好，
core 层零 chrome 依赖，Node 进程可直接复用 matcher / reducer。

**价值在读侧，不在写侧**：

```
你：「页面没数据，帮我 mock 一下」
AI → list_recent_requests    看到页面在请求 /api/goods/list，返回 404
AI → get_request_detail      确认参数是 { page, size, keyword }
AI → create_virtual_endpoint 造一个贴合参数结构的分页响应
你刷新页面 → 有数据了
```

全程一句话，没手抄 URL，没写 JSON。**现有任何 mock 工具都做不到这个闭环**，
因为它们只是 GUI，AI 看不见里面发生了什么。

**技术要点**（02 文档 §2.2 已调研）：

- 三段式：Claude Code ↔ MCP Server(Node) ↔ WebSocket ↔ 插件 SW
- 插件作为 WS client 主动连 localhost（插件里起不了 server）
- Chrome 116+ 起 WebSocket 活动会重置 SW 的 30s 空闲计时器；仍需 20s 心跳兜底
- 长连不稳时改用 offscreen document 持有连接
- 安全：配对码 + Origin 校验 + 端口随机化；读侧强制脱敏 + 域名白名单（Q11 已定）

**为什么排在 P2 而不是更前**：它是「新增能力」，而 P0/P1 是「补齐日常缺口」。
先把每天都要用的部分做顺，再扩展新场景。

- 痛感 ★★★☆☆ · 成本 ★★★★★ · 学习价值 ★★★★★
