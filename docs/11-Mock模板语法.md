# Mock 模板语法

> 更新：2026-08-06
> 实现：[`src/core/engine/mockjs.ts`](../src/core/engine/mockjs.ts) · 测试：[`tests/mockjs.test.ts`](../tests/mockjs.test.ts)

一行模板造一批「看起来像真的」的数据：

```json
{
  "list|10": [{ "id|+1": 1001, "name": "@ctitle(2,4)", "price|10-999.2": 1 }],
  "total|40-60": 1
}
```

---

## 1. 为什么自己实现，不引 Mock.js

| 理由 | 说明 |
| --- | --- |
| **体积** | 这段代码要打进注入脚本，而注入脚本在用户访问的**每一个页面**上加载。实测本模块给 `inject.js` 增加约 **6KB**（gzip），引 Mock.js 是约 **20KB**（gzip）。整个注入脚本现在 gzip 10.8KB，还不到 Mock.js 一个库的一半 |
| **不需要 eval** | 模板是纯数据，展开只是遍历 + 字符串替换。于是它在 CSP 禁了 `unsafe-eval` 的站点上**照样能用** —— 正好补上[动态响应](./10-动态响应Spike.md)的短板，两者互补而非重复 |
| **core 层合规** | 零依赖、零 chrome/DOM，可测，将来 MCP Server 能直接复用 |

按需加载这条路走不通：`xhr.send()` 是同步的，等不了 `import()`。这跟 09 §6.2 是同一个约束。

代价是只支持一个**子集**。差异见第 5 章 —— **不装作完全兼容**，比装了之后处处踩坑强。

---

## 2. 键上的规则：`"键|规则": 值`

| 规则 | 值的类型 | 效果 | 例子 |
| --- | --- | --- | --- |
| `\|n` | 数组 | 重复 n 次 | `"list\|10": [{...}]` → 10 项 |
| `\|min-max` | 数组 | 重复随机 min~max 次 | `"list\|1-5": [1]` |
| `\|n` | 字符串 | 重复 n 次 | `"sep\|3": "ab"` → `"ababab"` |
| `\|min-max` | 数字 | 范围内随机**整数** | `"age\|18-60": 1` |
| `\|min-max.d` | 数字 | 范围内随机**浮点**，d 位小数 | `"price\|10-99.2": 1` |
| `\|min-max.dmin-dmax` | 数字 | 小数位数也随机 | `"price\|10-99.1-3": 1` |
| `\|+n` | 数字 | 逐项递增，步长 n | `"id\|+1": 1001` → 1001, 1002… |
| `\|n` | 对象 | 随机取 n 个键 | `"o\|2": {a,b,c}` |
| `\|1` | 布尔 | 随机真假 | `"onSale\|1": true` |

几个说明：

- **`\|+n` 的第一项用模板里写的初值**，之后依次加 n。不同键各自计数，不会串号
- **每次请求重新展开**，递增从头开始 —— 两个请求不该拿到接着上次的号
- 展开后的键名**不带规则后缀**（`"list|10"` → `list`）
- **认不出的规则原样当键名**。`"a|b"` 就是字段名 `a|b`，不猜 —— 真有这种字段的接口不该被吃掉

## 3. 值里的占位符：`@名字` / `@名字(参数)`

**整串就是一个占位符时保留原始类型**，混在文本里时做字符串替换：

```json
{ "id": "@natural", "label": "编号 @natural 号" }
→ { "id": 4213, "label": "编号 8891 号" }
```

这个区分很重要 —— 否则前端 `typeof res.id === 'number'` 的判断会挂。

### 数字

`@natural(min,max)` · `@integer(min,max)` · `@float(min,max,dmin,dmax)` ·
`@id` · `@increment(step)` · `@guid`

### 文本

| 中文 | 英文 |
| --- | --- |
| `@cname` `@cfirst` `@clast` | `@name` `@first` `@last` |
| `@cword(min,max)` `@ctitle(min,max)` | `@word` `@title(min,max)` |
| `@csentence(min,max)` `@cparagraph(min,max)` | `@sentence(min,max)` `@paragraph(min,max)` |

`@boolean` · `@string(min,max)` · `@color`

### 联系方式与地区

`@email` · `@url` · `@domain` · `@ip` · `@phone` · `@city` · `@province`

### 时间

`@now(fmt)` · `@date(fmt)` · `@time(fmt)` · `@datetime(fmt)` · `@timestamp`

格式占位：`yyyy` `MM` `dd` `HH` `mm` `ss`。默认 `yyyy-MM-dd HH:mm:ss`（`@date` 是 `yyyy-MM-dd`）。
`@date` / `@time` / `@datetime` 取的是**近一年内的随机时刻**，`@now` 才是当前时间。

### 工具

- `@pick(a,b,c)` —— 从给定值里随机选一个。**枚举字段就用它**
- `@range(start,stop,step)` —— 生成数字数组

**认不出的占位符原样保留** —— 用户可能只是想写个 `@` 符号（如邮箱地址）。

## 4. 护栏

| 上限 | 值 | 为什么 |
| --- | --- | --- |
| 单个数组项数 | 1000 | `"list\|999999"` 是手滑就能打出来的，没上限直接把页面内存吃干净 |
| 总节点数 | 50000 | 防多层 `\|n` 相乘炸开（10 × 10 × 10 × …） |

超限时**不抛异常**，返回 `{"__mockStudioError__": "..."}`，DevTools 面板标红。
引擎跑在用户的每一个请求上，永不抛异常是铁律（09 §6.5）。

模板本身不合法 JSON 时同理，错误信息会直说是 JSON 的问题。
坏模板是确定性失败，连错 3 次会被熔断 —— 重试一万次也还是那个错，白烧 CPU。

## 5. 与 Mock.js 的差异

**必须知道的三条**：

| 项 | Mock.js | 这里 | 为什么 |
| --- | --- | --- | --- |
| `'arr\|1': ['a','b']` | 随机**取一个元素** | 重复数组，得到 1 个元素的**数组** | Mock.js 里同一个 `\|n` 在数组上有两种含义（取 n 个 / 重复 n 次），靠上下文猜，很容易写错。这里统一成「重复」，取值请用 `@pick(a,b)` |
| `'b\|1': true` | 有 1/2 概率取反 | 直接给随机布尔 | 分布一样，解释起来简单得多 |
| 占位符数量 | 上百个 | 约 40 个 | 只保留接口 mock 真正用得上的。`@image` `@county` `@zip` 之类没做 |

**没有实现**的还有：`@dataImage`、路径引用（`@/path`）、正则生成（`/\d{6}/`）、
函数模板（`'name': function(){}`）、自定义扩展（`Mock.Random.extend`）。

函数模板和自定义扩展需要 eval —— 那正是这条路存在的理由，做了就白做了。
真要写逻辑请切到**动态 JS**（[10 号文档](./10-动态响应Spike.md)），两者本来就是互补的。

## 6. 什么时候用哪个

| 需求 | 用 |
| --- | --- |
| 数据固定不变 | **静态 JSON**。可读性最好，别为了炫技用模板 |
| 要一批看起来像真的数据 | **Mock 模板** |
| 几份固定数据来回切 | **变体**（不是在模板里写分支） |
| 响应要随请求参数变（翻页、查详情、搜索） | **动态 JS** |
| 站点 CSP 禁了 `unsafe-eval` | **Mock 模板**（动态 JS 在那种站点用不了） |

三者都会走响应外壳 —— 「模板生成 data，外壳补公司统一格式」是最常见的组合。

---

## 7. 一个已知的取舍：数据每次都变

模板每次请求重新展开，所以刷新页面看到的值会变。

好处是能顺手验证「列表真的重新渲染了」；坏处是想对比两次渲染结果时会不方便。

实现里随机源是**可注入**的（`seededRandom`），把种子固定成请求 URL 的哈希
就能得到「同一请求永远同样数据」。目前没有做成开关 —— 等真的有人被这个绊到再说，
现在加只是多一个没人调的设置项。
